# Focused nearshore diagnosis — 2026-10-29

Subsequent status: the [integrated candidate correction and full rerun](nearshore-intact-closeout.md) pass both resolutions. This page preserves the preceding focused diagnostic evidence.

The discrepancy has a concrete implementation cause: the candidate-only memory optimization clipped shoreline lines before buffering them. This changes GEOS buffer geometry; a distance collar does not guarantee numerical equivalence for a discretized line buffer. Preserve complete original shoreline parts, buffer the selected intact parts, then clip the buffered result to the tile/cell. Do not clip or renode the lines first.

Eight largest-difference R8 cells were examined. The original unoptimized implementation on local context reproduced delivery exactly at six; the clipped optimization reproduced the differing full candidate. Removing tile clipping fixed those six. The other two also differed under a locally cropped reference because that reference introduced the same line-cutting operation at its outer collar. Selecting complete parts from the original global shoreline union, without clipping or re-union, reproduced delivery in all eight.

The final bounded acceptance covered all 38 R8 cells whose eligible area exceeded the unchanged tolerance: 190 checks across eligible area, valid bathymetry area, deep area, deep fraction and coverage fraction all pass. Maximum area error is 1.484295353293419e-7 m². Evidence is `nearshore-38-cell-correction.json`; original/local comparison is `nearshore-focused-diagnosis.json`; the intact-part diagnostic is `nearshore-intact-diagnosis.json`. These files and runnable diagnostic scripts reside in the task `full-study` directory. Fractions in the final evidence are independently reconstructed from the validated production area values.

All four historical manifest checksums match current retained files: GEBCO depth raster, SOURCE_COASTLINE.parquet, COASTAL_CONTEXT_WATER.parquet, and H3_MARINE_WATER_CLIPPED_GEOMETRY_RES_8.parquet. Repository checksums include the basename and file bytes, so raw SHA256 values must not be compared directly with manifest checksums. The diagnostic records both where relevant. The same inputs, EPSG:32610 projection and current dependencies produce the historical values when line segmentation is preserved; a changed CRS grid or dependency vintage is not needed to explain these failures. Historical resolved configuration survives as a hash, not a full dependency lock, but that missing evidence no longer blocks this specific diagnosis.

Local original/optimized shoreline selection masks match in the eight diagnostic fixtures and all 38 expanded fixtures. Full-candidate DEEP_TARGET_COMPONENT_IDS, NEAREST_DEEP_TARGET_COMPONENT_IDS, component status, distances and null masks already match delivery at both resolutions; area differences do not come from component-ID reassignment. R6 differences aggregate the affected R8 areas, but a corrected full R6 aggregation has not been executed or certified.

Decision: reject the original clipped-line candidate for promotion. The intact-part correction is validated on all 38 failing R8 area cells, but is not yet integrated into the full candidate-only runner or packaged defaults. No full-area rerun was launched: the previous run peaked at 1.91 GiB, and selecting intact source parts has not yet been measured across the whole context under the 2 GiB ceiling. A next bounded step can integrate intact-part selection and rerun under the existing 600-second/2 GiB guards after a representative memory preflight. Preserve original and failed candidate evidence. This is an implementation correction, not a scientific threshold or expected-value change.
